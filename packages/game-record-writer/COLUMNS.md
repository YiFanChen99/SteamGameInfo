# `STEAM` 工作表欄位對照表

新增 / 更新遊戲列的規則以這份表為準：改規則時先改這裡，再改程式，最後確認
[`test/__snapshots__/payloads.md`](test/__snapshots__/payloads.md) 的 diff 跟表一致。

- 程式一律用**標題名稱**找欄位（第 1 列），欄字母只供對照，欄位被搬動也不影響。
- 「Steam 來源」都是重新抓的 `?l=tchinese&cc=tw` 商店頁與全語言 appreviews（50 篇，依有幫助程度），不受目前頁面語言影響。SteamDB 區塊只在 Steam 商店頁讀得到。

## 修改機制

| 代號 | 意思 |
|---|---|
| **不動** | 無視這一欄，Sheet 上的值原封不動 |
| **覆蓋** | 有新值就整格換掉；沒有新值就不送（保留舊值） |
| **整合** | 讀舊值，只換掉規則管的部分，其他內容（手寫）保留 |
| **公式** | 新增時複製上一列的公式（相對參照跟著位移）；更新時不碰。server 端禁止寫入 |

「新增時」欄的**必有**＝新增一定會送；**預設**＝來源沒有值時改送的值；**留空**＝來源沒有值時不送。

### 細節

#### 原價
- 取本體的 `.game_purchase_action`：有折扣時取原價（`.discount_original_price`），否則取售價；排除訂閱方案、組合包和 Demo 區塊。
- 文字含 `free` / `免費` 時是 `0`。
- 更新時舊值和新值不同就回報「原價 舊 → 新（±差額）」。舊值是 `10000` 時不算變動。

#### 最低off
- 在 SteamDB 區塊的文字裡找第一個 `$ <數字>`（可含千分位逗號），`round((1 - 最低價 / 原價) × 100)`，最小 `0`。
- 原價 `0` → `100`；沒有原價 或是 有區塊但讀不到價格 → 空值。
- 沒有 SteamDB 區塊：新增寫 `0`；更新不動。
- 區塊是按下按鈕時才讀（SteamDB 擴充在頁面載入後才補上）。SteamGifts 上沒有這個區塊，所以那裡的更新不會動最低off。

#### 特
- 語言標記：介面支援 繁體中文 → `繁`；否則 簡體中文 → `簡`；否則 英文 → `英`；都不支援 → `X`。
- 舊值的語言標記也可能是這 4 種以外的手寫字串（舊值拿掉 `Demo` 後剩下的部分）。只在發現語言優先度更高時取代該語言。
   - 優先度：`繁` > `簡` > `英` > 手寫字串 > `X`（舊的 `無` 也算 `X`）> `!`。同等或較低時保留舊值，所以不會降級。
   - 例：舊 `簡(機翻)`，頁面支援繁中 → `繁`；頁面都不支援 → 保留 `簡(機翻)`。
- 頁面沒有語言表：新增寫 `!`（未知）；更新保留舊值。
- `Demo`：頁面有 Demo 就加，沒有就拿掉。
   - 例：舊 `英`，頁面支援簡中、有 Demo → `簡 Demo`。

#### 備註
- 新增：
   - 遊戲特點敘述：爬頁面資訊，可能允許使用者輸入。規則定之前寫 `TODO。`。
   - 外加結構：`[YY/MMEA。]` 只在搶先體驗時加；接著是遊戲時長 `中位<n>H，3rd.高<n>H。`。
      - `YY/MM` 補零，例如 `26/03EA。`；上市日期不是完整日期時照 Steam 原文，例如 `2026 年第四季EA。`。
      - 時長：取回來的評論作者的總遊玩時數，四捨五入成整數小時；中位數；第 3 高需要至少 5 篇，否則寫 `-`；完全沒有評論時中位也是 `-`（舊 scraper 留下的 `NaN`）。
- 更新：更新時應該只取代遊戲時長部分，其他全維持。
