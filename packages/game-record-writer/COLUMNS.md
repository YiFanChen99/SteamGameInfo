# `STEAM` 工作表欄位對照表

新增 / 更新遊戲列的規則以這份表為準：改規則時先改這裡，再改程式，最後確認
[`test/__snapshots__/payloads.test.ts.snap`](test/__snapshots__/payloads.test.ts.snap) 的 diff 跟表一致。

- 程式一律用**標題名稱**找欄位（第 1 列），欄字母只供對照，欄位被搬動也不影響。
- 「Steam 來源」都是重新抓的 `?l=tchinese&cc=tw` 商店頁與全語言 appreviews（50 篇，依有幫助程度），不受目前頁面語言影響。SteamDB 區塊只在 Steam 商店頁讀得到。

## 修改機制

| 代號 | 意思 |
|---|---|
| **不改** | 不送這一欄，Sheet 上的值原封不動 |
| **覆蓋** | 有新值就整格換掉；沒有新值就不送（保留舊值） |
| **整合** | 讀舊值，只換掉規則管的部分，其他內容（手寫）保留 |
| **公式** | 新增時複製上一列的公式（相對參照跟著位移）；更新時不碰。server 端禁止寫入 |
| **手動** | 程式從不寫，由使用者自己填 |

「新增時」欄的**必要**＝新增一定會送；**預設**＝來源沒有值時改送的值；**留空**＝來源沒有值時不送。

## 細節

### 原價
- 取本體的 `.game_purchase_action`：有折扣時取原價（`.discount_original_price`），否則取售價；排除訂閱方案、組合包和 Demo 區塊。
- 文字含 `free` / `免費` 時是 `0`。
- 更新時舊值和新值不同就回報「原價 舊 → 新（±差額）」。舊值是 `10000` 時不算變動。

### 最低off
- 在 SteamDB 區塊的文字裡找第一個 `$ <數字>`（可含千分位逗號），`round((1 - 最低價 / 原價) × 100)`，最小 `0`。
- 原價 `0` → `100`；沒有原價 → 不送；有區塊但讀不到價格 → `-`。
- 區塊是按下按鈕時才讀（SteamDB 擴充在頁面載入後才補上）。SteamGifts 上沒有這個區塊，所以那裡的更新不會動最低off。

### 特
- 語言標記：介面支援 繁體中文 → `繁`；否則 簡體中文 → `簡`；否則 英文 → `英`；都不支援 → `X`；頁面沒有語言表 → 保留舊標記，沒有舊標記才寫 `!`。
- `Demo`：頁面有 Demo 就加，沒有就拿掉。
- 其他標籤（手寫的）原樣保留，排在最後。舊 steam_lookup 寫的 `無` 也當成語言標記替換掉。
- 例：舊 `英 多人`，頁面支援簡中、有 Demo → `簡 Demo 多人`。

### 備註
- 新增：`[上市日期EA。]` 只在搶先體驗時加；接著是 `中位<n>H，3rd.高<n>H。`。
- 時長：取回來的評論作者的總遊玩時數，四捨五入成整數小時；中位數；第 3 高需要至少 5 篇，否則寫 `-`；完全沒有評論時中位也是 `-`。
- 更新：只把 `中位…H，3rd.高…H。` 那一段換成新值（包含舊 scraper 留下的 `NaN`），EA 段和手寫內容不動；舊值沒有時長段時接在最後。
- 例：舊 `2026/3/5EA。中位40H，3rd.高300H。等正式版` → `2026/3/5EA。中位125H，3rd.高725H。等正式版`。
